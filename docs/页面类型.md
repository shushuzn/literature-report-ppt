# 页面类型速查

一页 = `deck` 列表里的一项。`type` 决定版式，其余字段决定内容。
新增页面不必改代码，从下表挑一个类型填字段即可。

## 通用约定

| 项 | 规则 | 说明 |
|---|---|---|
| 字号 | 由 `style.body_pt` 定（默认 20） | 低于 `style.min_pt` 生成时报错 |
| 中文字体 | 由 `style.cn_font` 定（默认微软雅黑） | 写 `a:ea` 节点，不是 `font.name` |
| 英文字体 | 由 `style.en_font` 定（默认 Times New Roman） | 数字与西文自动用它 |
| 配色 | 黑 / 深灰 / 浅灰 | 不含色相，改 `style` 的 `ink` 系列可整体换色 |
| 图注 | **只能一行** | 超过一行生成时告警：`P{n} 图注超过一行` |
| 页眉 | 由 `title` 自动生成 | 页标题 + 细分隔线，不需要自己画 |
| 讲稿 | 任意页都可写 `notes` | 写进 PowerPoint 演讲者备注，不投影、不计入字号检查 |

## 1. `cover` 封面

| 字段 | 必填 | 说明 |
|---|---|---|
| `title_cn` | ✓ | 主标题，38pt 加粗居中 |
| `kicker` | | 主标题上方的疏排小字（20pt），一般**不写**；见下方约定 |
| `title_en` | | 英文副题，字符串或列表（列表 = 多行） |
| `presenter` | | 渲染为「汇报人：×」 |
| `advisor` | | 渲染为「指导老师：×」 |
| `meta` | | 追加行（以日期为主），字符串或列表 |

四个可选块（`kicker`、`title_en`、`presenter`/`advisor`、`meta`）都可以整段不给：
封面只留主标题也是完整版面。

**封面不放三样东西**，合规核对会判 ERROR（`compliance.py` 的 `COVER_FORBID`）：

| 不放 | 放哪 |
|---|---|
| 期刊卷期页，如 `Chem. Rev. 2026, 126(15), 8517−8598` | 第 2 页「发表期刊」字段 |
| DOI | 同上；讲稿里念出来也行，不用投影 |
| 「文献汇报」这类眉标 | 不写。投影现场人人都在汇报，写了不增加信息 |

这几项在封面重复一遍，只会把注意力从题目上分走。确需例外的（比如汇报本身
就以「文献汇报方法」为题），在 `compliance.cover_allow` 里列出放行片段。

整块按内容总高反推起点并垂直居中：加眉标、删一行信息都不用重调坐标。

## 2. `section` 章节过渡页

| 字段 | 必填 | 说明 |
|---|---|---|
| `index` | | 两位序号，如 `"01"`（84pt，浅灰） |
| `title` | ✓ | 章节名，40pt 加粗 |
| `lead` | | 一句导语，字符串或列表 |

> **坑**：序号字段必须写 `index`。YAML 1.1 会把裸键 `no` / `yes` / `on` / `off`
> 解析成布尔值，`no: "01"` 实际得到 `{False: "01"}`，序号会静默消失。

## 3. `compare` 两栏对照

适合「旧 vs 新」「优点 vs 代价」——两栏同构，让对照关系一眼可见。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | 页标题 |
| `left` / `right` | ✓ | `{tag, label, points}`，两栏结构相同 |
| `tag` | | 栏目上方的小标签（20pt 灰），如「旧范式」 |
| `label` | ✓ | 栏目名，24pt 加粗 |
| `points` | ✓ | 字符串，或 `{name, desc}` |
| `item_gap_pt` | | 条目间距，默认 14pt |

两栏高取大者对整块垂直居中，中间一条竖线只画到内容底部——不做两张卡片并排，
避免「两个盒子夹一条缝」的观感。

## 4. `fields_image` 左图 + 右字段

适合「一图交代出处」：文献信息、样品参数、实验条件。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | 页标题 |
| `image` | ✓ | 相对 `base_dir` 的图片路径 |
| `caption` | | 图注，一行以内 |
| `fields` | ✓ | `[{label, value}]`，`value` 可为字符串或列表 |

标签加粗、与首行值同行起排；值折行时次行按悬挂缩进退到值左端。

标签列宽取本页最长标签（短标签用全角空格补齐），所有值从同一条竖线起排。
不统一时会露馅：`分区` 只有两个字，值就比上下行左移半个字宽，整列是错开的。
标签列宽超过右栏 42% 时放弃统一，退回各字段自然宽度——值参差总好过
值那一栏窄到每行只剩几个字。

字段间隔按剩余高度自动算，整栏铺满。

## 5. `image_cards` 左图 + 右卡片竖排

适合「一图对几条结论」：机理与组分、应用场景。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` `image` | ✓ | |
| `caption` | | |
| `cards` 或 `items` | ✓ | `[{name, desc}]`；`name` 省略即为无标题卡（放流程、结论） |

卡片高度由文案反推；内容偏少时卡片会自动长高填满栏位，不会在底部留空。

## 6. `image_grid_cards` 上方一组图 + 下方卡片栅格

适合「多图对多结论」：性能与成因。图与卡片共用同一套栅格，列中线对齐。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | |
| `images` | | `[{path, caption}]`，建议 2 张；省略则只有卡片区 |
| `items` | ✓ | `[{name, data, cause}]` 或 `[{head, body}]` |
| `n_col` | | 列数，默认 2 |

`name + data` 并排成卡片标题（全角空格分隔），`cause` 渲染为「成因：…」。

## 7. `cards_grid` 纯卡片栅格

适合「无图但要多条并列」：结论、局限、后续计划。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | |
| `columns` | | 1 = 整栏竖排（默认），2 / 3 = 栅格 |
| `items` 或 `cards` | ✓ | `[{name, desc}]` |

余量处理：行间距封顶 0.45in，剩余高度摊给卡片（单卡最多长高 0.9in），
再多的余量让整块垂直居中——不会出现「两行卡片被拉到页面两端」。

## 8. `bullets` 要点列表

适合「纯文字、层层递进」：背景、启示、时间线。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | |
| `lead` | | 导语，字符串或列表 |
| `items` | ✓ | 字符串，或 `{name, desc}`（name 加粗） |
| `marker` | | 行首符号，默认 `· ` |
| `lead_pt` | | 导语字号，默认 24pt（条目固定 20pt） |
| `gap_pt` | | 导语与条目之间的段前距，默认 16pt |
| `item_gap_pt` | | 条目之间的段前距，默认 0（只有行距）。4 条以上要点建议 14–18pt，否则挤成一块 |
| `align_desc` | | 是否把说明文字对齐到同一列，默认 true；`false` 则紧贴名称起排 |

`{name, desc}` 写法的条目会取最宽的 name 作为公共列宽，说明从该列起排，
续行也停在该列（悬挂缩进）。不这么做，说明一行写不完时次行会退回左边距，
四条要点看着像一坨。名称列最多占版心 42%（`style.bullets_hang_max`），
超出就退回自然排。

`gap_pt` 与 `item_gap_pt` 取值不同时，版式验收的「段间距」维度会判极差超标，
两处要给同一个值。

整块在正文区垂直居中：内容不满时上下留白相等，不会「顶在上面、下面空半页」。
居中由本函数按度量结果算好起点，不靠文本框的 MIDDLE 锚点——盒子远高于文字时
锚点会系统性偏下（实测上下留白 1.7 : 1.0）。

## 9. `timeline` 时间轴（综述用）

综述要回答「这个领域怎么走到今天」，卡片排不出来：卡片是并列的，发展是先后。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | 页标题 |
| `tracks` | ✓ | `[{name, nodes}]`，一条轨 = 一条并行线索 |
| `tracks[].name` | | 轨名，右对齐排在轴线左端，像行标题；全都不写则不留那一列 |
| `nodes` | ✓ | `[{year, head, desc}]` |

`year` 写年代，`head` 写这一步做成了什么，`desc` 写它解决了上一段的什么问题。
三个都要写：只给年份读者不知道发生了什么，只给名词读者不知道先后。

**横轴按序号均分，不按年份比例。** 1853 与 2006 相隔一百五十年，按真实比例排，
十九世纪那几个节点会挤成一条竖线、近二十年的又叠在一起。均分是「讲得清」
优先于「坐标准」，年代仍写在节点上，间距不等于时长这件事读者看得出来。

节点方块压在轴线上（几何中心对齐，逐像素核过），文字一律从轴线往下排。
两轨以上时节间距封顶 1.10in，剩余空间对半分给上下，整块落到视觉中线。

**几条轨、每轨几个节点，由内容决定**：常见写法是「认识线 + 材料线」各 5–6 个，
两条线在某个节点会合（本项目是 2006 年亚纳米孔的反常电容）。

## 10. `stages` 阶段带（综述用）

同一条线逐级演进，看纵深——每一步解决了什么、又欠下什么。

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | 页标题 |
| `stages` | ✓ | `[{year, name, desc, cost}]` |
| `year` | | 年代，22pt 大字靠右，做左侧锚点 |
| `name` | ✓ | 这一级的做法（加粗）。写名词短语（`活化刻蚀`、`二氧化硅与沸石模板`），
做法与得失交给 `desc`/`cost`——阶段名写成「活化法提高比表面积」，就和卡片页的标签不是一种语体了 |
| `desc` | | 做法本身 |
| `cost` | | 代价。建议直接以「代价是…」起句，读者不用猜这一行是什么 |

与 `timeline` 的分工：`timeline` 看全景（几条线各走了几步），`stages` 看纵深
（一条线每一步的得失）。综述的常见结论是「每一步都在还上一步欠的账」，
`cost` 那一行就是这笔账，不写就等于只讲成绩。

竖线只画第一级到最末一级的跨度，不拉满整页——拉满会给「没讲完」的空档画上句号。

## 组合建议

| 汇报类型 | 页数 | 推荐页面序列 |
|---|---|---|
| 单篇文献精读（5 分钟，讲稿按 7 分钟备料） | 5 | cover → fields_image → image_cards → image_grid_cards → image_cards |
| 单篇文献精读（10 分钟） | 8–10 | cover → section → bullets → section → fields_image → section → image_cards → image_grid_cards → cards_grid → bullets |
| 领域综述（5 分钟） | 8 | cover → fields_image → cards_grid（核心命题）→ timeline（双轨）→ stages（四级台阶）→ image_cards（转折点）→ cards_grid（卡点）→ bullets（方向） |
| 领域综述（12–15 分钟） | 12–15 | cover → section×n，每段 = timeline / stages 与 image_cards 交替 |

综述的页序和研究论文不同：研究论文是「一篇工作怎样，为什么这样」，
综述是「文献 → 在论证什么 → 发展 → 路线 → 转折 → 卡点 → 方向」。
不要把「制备 / 性能 / 应用」三段套到综述上——那是单篇的骨架。

**转折点要放在路线之后，不要放在路线之前。** 这一条是改出来的：早先把
`image_cards`（2006 年亚纳米孔反常）排在 `stages`（四级台阶）前面，于是讲完
一个纳米尺度的机制，下一页退回到 1990 年前的活化法，听众刚竖起来的注意力
被按回去，时间和尺度同时倒车。换成「台阶 → 转折」之后，衔接就成了因果：
台阶把孔径做到 1 nm 以下，反常正好出现在这个尺度上，取完证据接着数瓶颈。
转折点在讲稿里要有一句回指上一页的话（「这一页回到第二级台阶的那个尺度」），
否则它仍像另起一段。

「在论证什么」这一页别省。少了它，后面几页各讲各的，听众不知道它们为什么
按这个顺序出现；第一次做这份综述时就是六页直接进时间轴，读起来很突兀。

一个 `section` 后面跟 2–3 个内容页最稳。连续三页同类型会显得平。

## 加一种新版式

1. 在 `pptkit/pages.py` 写 `def my_layout(deck, page, base):`
2. 注册：`PAGES["my_layout"] = my_layout`，并在 `REQUIRED_KEYS` 写必填字段
3. 在 `docs/页面类型.md` 补一节

版式函数只读 `page` 字典；纵向位置一律由内容高度反推或 `distribute()` 均分，
不要写死 y 值，否则换内容就会溢出。
