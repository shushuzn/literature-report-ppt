# 合规核对：核什么、怎么判

核对的对象是**生成出来的文件是否符合这个项目的配置**，不是「是否符合某一份通知」。
每次汇报的页数、时限、结构都可能变，变的是 `content.yaml`，核对方法不变。

三个输入：

| 输入 | 从哪来 | 提供什么 |
|---|---|---|
| `content.yaml` | 项目目录 | `compliance` 段的全部阈值 |
| `.pptx` | `tools/build.py` 产出 | 页数、字体、字号、配图、必填文字 |
| 渲染图 | `tools/export_preview.ps1` 导出 | 越界、重叠、居中、孤字等版面问题 |

## 阈值从配置读，不从文档抄

`compliance` 段的字段决定判什么、判到多少：

```yaml
compliance:
  max_pages: 5                 # 页数上限
  limit_min: 5                 # 讲稿限时（分钟），不写则不查时长
  time_buffer: 0.4             # 备料冗余，加在限时上
  chars_per_min: 220           # 语速
  require_image_pages: [2,3,4,5]   # 哪些页必须有图
  required_text:               # 哪些页必须出现哪些字
    1: [汇报人]
    2: [论文题目, 发表期刊]
```

要求变了就改这几个数，代码和核对方法都不用动。**文档里不写死任何一次的数**：
写进去就成了隐形的第二套标准，下次汇报必然对不上。

字体、字号下限、配色在 `pptkit/style.py`，属引擎默认值，与单次要求无关；
某次要求不同（例如允许 18pt），在 `content.yaml` 的 `style` 段覆盖，
或按主题新建一份默认值，不必改引擎。

## 九道门禁各管一段

| # | 门禁 | 脚本 | 判什么 | 时机 |
|---|---|---|---|---|
| 1 | 文风体检 | `style_check.py` | AI 腔句式、标题标点、用词密度 | 动手前 |
| 2 | 孤行预检 | `check_text.py` | 按各页版式算宽度，末行占比过低 | 生成前 |
| 3 | 综述门禁 | `review_check.py` | 时间轴在不在、节点数与跨度够不够、有无单篇口吻 | 生成前 |
| 4 | 讲稿时长 | `note_budget.py` | 必讲 ≤ 限时；全文 ≤ 限时 × (1+冗余) | 生成前 |
| 5 | 事实核对 | `fact_check.py` | 配置里每个数字能否在原文找到 | 生成前 |
| 6 | 生成自检 | `build.py` | 字号下限、版面是否溢出 | 生成时 |
| 7 | 预览导出 | `export_preview.ps1` | 逐页 PNG，且必须比 pptx 新 | 生成后 |
| 8 | 合规核对 | `check.py` | 页数 / 字体 / 字号 / 配图 / 必填项 / 每页字数 / 封面不重复出处 | 生成后 |
| 9 | 版式验收 | `audit_all.py` | 全页 × 九维度（越界、重叠、居中、孤字…） | 渲染后 |

第 7 道是第 9 道的前提。审计量的是像素，图比稿子旧就等于审上一版，
所以：`verify.py` 每次自动重导；`audit_all.py` 单独跑时会核对图的时间戳，
发现旧图或缺图直接退出码 2，不出「全部通过」。

第 3 道与第 5 道在缺少输入时会跳过：没有 `review:` 段就跳过综述门禁，
没有 `_src/paper.txt`（或 `paper_clean.txt` / `paper.md`）就跳过事实核对，
两者都不算失败。其余七道对研究论文与综述一视同仁——它们判的是
「这一页做得对不对」，综述多出来的那一问是「整篇讲的还是不是这个领域」。

一条命令跑完：

```bash
python tools/verify.py projects/<项目>/content.yaml
python tools/verify.py --all          # 全部项目
python tools/verify.py --skip-audit   # 只跳过第 9 道版式验收（没有 PowerPoint 时）
```

## 输出怎么读

第 8 道把统计摊开：页数、run 数、字号分布、各页配图数、各页字数、字体违规数。
数字对不上配置就是不合格，不需要人来判断「大概可以」。

第 9 道逐页打印九个维度，任一维度越界即该页失败；失败会指出是哪个文本框、
差多少磅。这张表比任何目测都可靠，也是唯一能发现「文字压在框线上」的手段。

## 记录写在哪

每个项目的核对结果写在该项目目录下的 `核对记录.md`，与 `content.yaml` 同级：

```
projects/<项目>/
├── content.yaml
├── 核对记录.md     本项目的核对结果与整改历史
└── figs/
```

`docs/` 只放与项目无关的方法与规范。项目记录放进 `docs/` 会带来两个后果：
一是文档目录随项目数量膨胀，二是后来的人会把某个项目的数值当成通用标准。
