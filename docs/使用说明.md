# 使用说明：换一篇文献 / 换一个课题怎么做

本项目是**通用汇报 PPT 生成器**：版式、字体字号、合规门禁都在引擎里，
**页数与页序不写死**，由内容配置里的 `deck` 列表决定。
换文献或换课题，只改 `projects/<项目>/content.yaml` 与配图，不写代码。

- 页面类型速查：[页面类型.md](页面类型.md)
- 文风要求（标题写法、AI 腔清单）：[文风规范.md](文风规范.md)
- 常用版式的可运行样例：`projects/_template/content.yaml`
- 综述版式（`timeline` / `stages`）：见[页面类型.md](页面类型.md) 第 9–10 节

## 目录分工

```
pptkit/                引擎（与具体文献无关，一般不用改）
├── style.py           Style 对象：字体、字号、画布、版心、配色   ← 调风格改这里
├── theme.py           默认样式的别名（旧脚本兼容，不随配置变）
├── flow.py            文字流检查：换行宽度、孤行判定（生成与预检共用）
├── metrics.py         文本度量：估算换行数、块高、末行占比
├── engine.py          Deck：文本 / 卡片 / 图片框 / 讲稿备注
├── pages.py           页面类型注册表（10 种版式，一页一个函数）  ← 加版式改这里
├── template.py        deck 配置解析与组装（兼容早期五段式配置）
└── compliance.py      合规核对（页数/字体/字号/配图/必填项）

projects/<项目名>/
├── content.yaml       该项目的全部内容（页面序列 + 文字）  ← 换课题只改这个
└── figs/              从论文抽取的配图

tools/
├── verify.py          全检入口：依次跑下面几道门禁
├── style_check.py     文风体检（对偶转折、口号收尾、空标题、用词密度）
├── check_text.py      孤行预检（断行是否留下孤儿字，逐页按版式算宽度）
├── review_check.py    综述门禁：时间轴在不在、跨度够不够、有没有串成单篇口吻
├── note_budget.py     讲稿时长门禁：必讲 ≤ 限时，全文 ≤ 限时 × 语速 × (1 + 冗余)
├── build.py           生成 PPT（含字号与版面溢出检查）
├── check.py           合规核对（页数/字体/字号/配图/必填项）
├── audit_all.py       版式验收：全页 × 九维度（核心门禁）
├── audit_gaps.py      间隔诊断：量指定区域内每行位置与行间距
├── export_notes.py    讲稿导出：notes → 纯文本（可选 Markdown），按字数估每页用时
└── export_preview.ps1 导出逐页预览图

requirements.txt       运行依赖（python-pptx / PyYAML / Pillow / numpy）
```

### 版式验收的九个维度

`audit_all.py` 对**每一页**都跑一遍下列九项，不挑页：

| # | 维度 | 判定方式 |
|---|---|---|
| 1 | 越界 | 所有元素是否都在页面内 |
| 2 | 重叠 | 非包含关系的元素是否互相压盖 |
| 3 | 图片贴合 | 图片外框与图片真实比例是否吻合（死区 ≤ 12%） |
| 4 | 框内居中 | 面板内文字上下边距是否对称（读 XML 即可判） |
| 5 | 卡内留白 | 上下留白 ≥ 0.10in 且对称；有标题的卡片，标题与正文间隔 ≥ 8pt |
| 6 | 孤行 | 末行占比是否 ≥ 0.18 |
| 7 | 段间距 | **同一文本框内**的段落间隔极差是否 ≤ 6pt |
| 8 | 卡片间距 | 同栏相邻卡片的间距极差是否 ≤ 6pt |
| 9 | 栏内填充 | 同排并列各栏底部留白是否 ≤ 0.35in |

第 7 项只适用于「一个文本框里排多个同类条目」的版面（如 P2 的字段列表）。
封面刻意采用层级间距（主标题、副标题、姓名各行距不同），不适用第 7 项，
改由「封面分隔线上下是否对称」单独检查。

第 7 项和第 8 项分工要分清：**卡内标题与正文的间隔**属于文本框内部（第 7 项），
**卡片与卡片之间的间距**属于版面（第 8 项）。早期把两者混在一栏里比，
卡内层级间隔一放大就误报极差 40pt。

第 9 项针对「某栏内容少、下方空一大片」。修法是让间隔按剩余高度自动算
（见 `template.literature`），使整栏填满；间隔本身仍恒定不变。

## 三步换文献

### 1. 抽图

把论文 PDF 的首页与关键插图抽到该项目的 `figs/` 目录：

```python
import pymupdf, os
d = pymupdf.open("论文.pdf")
os.makedirs("projects/新项目/figs", exist_ok=True)

# 首页截图（3.2 倍分辨率，保证 20pt 下清晰）
d[0].get_pixmap(matrix=pymupdf.Matrix(3.2, 3.2)).save("projects/新项目/figs/page1.png")

# 正文插图（逐页导出，过滤过小图片）
for pno in range(d.page_count):
    for i, info in enumerate(d[pno].get_images(full=True)):
        im = d.extract_image(info[0])
        w, h = im["width"], im["height"]
        if w < 300 or h < 220:
            continue
        open(f"projects/新项目/figs/p{pno+1}_{i}.{im['ext']}", "wb").write(im["image"])
```

**图片清晰度要求**：正文图建议宽 ≥ 1500 px，首页截图建议 3 倍以上渲染。

### 2. 填内容

复制 `projects/_template/content.yaml` 到新目录，改内容。核心是 `deck` 列表——
**列表里每一项就是一页**，页序即顺序，页数即长度：

```yaml
out: projects/新项目/材料/汇报.pptx
base_dir: projects/新项目          # 图片路径的基准目录
title_mode: label                  # 文献汇报/综述用 label（标题=任务名）；
                                   # 讲自己的工作删掉这行（默认 thesis，标题写判断）
data_density: true                 # 综述项目可开：查「一张卡里塞几个数」，
                                   # 默认关闭；研究论文页数据就是内容，别开

deck:
  - type: cover                    # 封面
    title_cn: 中文标题
    title_en: [English line 1, line 2]
    presenter: 姓名
    advisor: 指导老师
    notes: |                       # 讲稿写进演讲者备注，任意页都能加
      各位老师好，我汇报的是……

  - type: section                  # 章节过渡页
    index: "01"                    # 注意用 index，YAML 会把裸键 no 当成布尔
    title: 研究背景
    lead: [一句导语]

  - type: fields_image             # 左图 + 右字段（文献信息）
    title: 汇报文献信息
    image: figs/page1.png
    caption: 论文首页
    fields:
      - {label: 论文题目, value: [...]}   # value 支持字符串或多行列表
      - {label: 发表期刊, value: 期刊名（卷期）}

  - type: image_cards              # 左图 + 右卡片竖排（机理 / 应用）
    title: 设计与机理
    image: figs/f1.png
    caption: Fig.1
    cards:
      - {name: 组分/设计, desc: 一句话作用}

  - type: image_grid_cards         # 上方一组图 + 下方卡片栅格（性能）
    title: 关键性能及成因
    images:
      - {path: figs/f3.png, caption: Fig.3}
      - {path: figs/f4.png, caption: Fig.4}
    items:
      - {name: 性能名, data: 数值 + 基准, cause: 成因}

  - type: cards_grid               # 纯卡片（结论 / 局限 / 计划）
    title: 结论与局限
    columns: 2
    items:
      - {name: 结论一, desc: ...}

  - type: compare                  # 两栏对照（旧 vs 新）
    title: 从「筛材料」到「设计材料」
    left:  {tag: 旧范式, label: 自上而下, points: [...]}
    right: {tag: 新范式, label: 自下而上, points: [...]}

  - type: bullets                  # 要点列表
    title: 启示
    items:
      - {name: 可借鉴, desc: ...}
      - 纯字符串条目也支持

compliance:                 # 核对期望值
  max_pages: 10             # 不写则以 deck 的实际页数为上限
  require_image_pages: [5, 7, 8]
  required_text:
    1: [汇报人]
    5: [论文题目, 发表期刊]
```

字段级说明与各类型的适用场景见 [页面类型.md](页面类型.md)。

> **旧五段式配置仍然可用**：`cover` / `literature` / `mechanism` / `performance` /
> `application` 五段会被自动转成五页（`pptkit.template.legacy_pages`），
> 文风、讲稿时长、事实核对等门禁也都能读。新项目建议直接用 `deck` 列表。

### 3. 生成并核对

```bash
# 全检（推荐）：文风 → 孤行 → 综述 → 讲稿时长 → 事实核对 → 生成 → 预览 → 合规 → 版式验收
python tools/verify.py projects/<文献名>/content.yaml
python tools/verify.py --all                                 # 跑全部项目

# 讲稿 → 纯文本（每页字数与用时；加 --md 输出 Markdown）
python tools/export_notes.py projects/<文献名>/content.yaml

# 也可以单跑
python tools/style_check.py projects/<文献名>/content.yaml   # 文风体检
python tools/check_text.py  projects/<文献名>/content.yaml   # 孤行预检
python tools/review_check.py projects/<文献名>/content.yaml  # 综述门禁（无 review 段则跳过）
python tools/note_budget.py projects/<文献名>/content.yaml   # 讲稿时长
python tools/build.py       projects/<文献名>/content.yaml   # 生成
python tools/check.py <pptx> -c projects/<文献名>/content.yaml
python tools/audit_all.py <pptx> <preview目录>               # 需先导出预览图
python tools/audit_gaps.py <png> x0 y0 x1 y1                 # 单栏间隔诊断
```

退出码 0 表示通过，非零表示有未过项。生成脚本还会在**字号低于 `style.min_pt`**
或**版面放不下**时告警。预览图由 `verify.py` 自动重导，不用手工调脚本。

改完版式务必导出预览图目视确认（脚本不再内置任何默认路径，两个参数都必填）：

```powershell
powershell -File tools/export_preview.ps1 -Ppt projects/<项目>/材料/汇报.pptx -Out projects/<项目>/材料/preview
```

## 五条硬性注意（另附四条）

### 一、同一栏内多段文字，间隔交给段间距，不要逐段定位

若给每段单独定位（估算行数 → 分配高度 → 均分间隔），估算偏大的段会留下
内部空隙，使视觉间隔忽大忽小。实测过一次 P2 的字段间隔为
**19.8 / 45.0 / 18.0 / 18.6 / 45.0 pt**，极差 25pt，非常难看。

正确做法见 `engine.groups_text()`：**整栏只用一个文本框**，段间用
`paragraph.space_before` 控制间隔。这样间隔由 PowerPoint 保证恒定，
与行数估算是否准确无关。修后实测为 17.4 / 19.2 / 17.4 / 18.0 / 18.6 pt。

（有边框的卡片是另一回事：边框定义了盒子、文字在盒内居中，
所以用 `distribute()` 定位卡片本身没问题。）

### 二、文本框内部边距必须归零

PowerPoint 文本框默认上下留 0.05 英寸、左右留 0.1 英寸。不清零的话，
版面算出的宽度与实际可用宽度不符，文字会被挤到下一行并整体下移，
表现为「文字在框里偏下、底部贴边」。`engine.text()` 已统一清零。

### 三、面板内文字交给 PowerPoint 居中；但整页文字块要自己算位置

早期实现用「两个文本框 + 固定 y 偏移」摆标题和正文，结果上下边距不等
（实测上 18px、下 39px）。改成**一个文本框 + MIDDLE 锚点**后由
PowerPoint 负责居中，12 个面板实测上下边距差均 ≤3px。

**但盒子远高于文字时，MIDDLE 锚点会系统性偏下**：文本框高 5.98in、文字只有
3.2in 时，实测上下留白为 1.7 : 1.0，差值 0.4in。原因是 PowerPoint 以它自己的
行高模型排版，文字超出盒子高度时只向下溢出，并不对称。所以：

- **卡片**（盒子高度由内容反推，二者接近）→ 用 MIDDLE 锚点；
- **整页文字块**（`bullets` / `compare`）→ 自己按度量算起点，盒子高度取估算值，
  再配 MIDDLE 锚点：估算偏小时文字上下各溢出一点，视觉仍是居中。

### 四、字号提到 20pt 后不能凭经验估高度

20pt 中文在固定宽度下的实际换行数远超直觉。必须用 `metrics.block_h()` /
`est_lines()` 按字体度量反推，否则文字溢出边框、相邻单元格重叠。
经验系数（Times New Roman 20pt 实测标定）：中日韩字符宽 ≈ 1.00 em，
数字 ≈ 0.50，大写字母 ≈ 0.60，小写字母 ≈ 0.42，空格 ≈ 0.25，西文标点 ≈ 0.32；
行高 ≈ 1.24 × 字号；可用宽度按 0.97 折算留余量。

> 早期对全部西文统一取 0.52 em，对以大小写字母为主的文本会高估约三成，
> 导致行数多算、进而使版面留白不均。现已按字符类别分别取值。

### 五、图片外框必须按图片真实比例贴合

固定尺寸的外框会把图片缩在中间、留下大片死区（曾出现 65% 死区）。
一律用 `deck.image_framed()` / `deck.image_row()`，它们先按图片真实宽高比
算出显示尺寸，再画恰好贴合的外框。

### 附一：中文断行的孤行问题

中文长句换行后，末行若只剩一两个字或一个标点（如「号」「。」），很难看。
`tools/check_text.py` 会按末行占比找出这些条目（阈值 0.18）。两种改法：

1. **收敛为一行**：把句子改短
2. **显式断行**：把 `value` / `desc` 写成列表，每项一段，自己控制断点
   ```yaml
   value:
     - Biomimetic layered,
     - ecological, advanced, multi-functional
   ```

`tools/audit_all.py` 会在渲染图上复核，检测实际是否仍有孤行。

### 附二：单图页的左栏宽由图片比例决定，且不能挤窄右栏

`template.column_split()` 取两个条件的较小值：**图片按比例铺满可用高度所需的
宽度**，与**保证右栏不小于 `COL_R_MIN = 6.0in` 的最大左栏宽**。

若只按图片算，图越宽左栏越宽、右栏被压缩——实测过右栏内宽从 402pt 掉到 370pt，
同一句话就多出一个换行，工艺行断出只剩 2% 宽的末行。6.0in 是 20pt 下约容
20 个汉字不换行的底线。

被右栏下限截短时，图片填不满高度，`image_framed()` 会把图连图注在栏内垂直居中，
上下均分余量（否则余量全堆在图下方）。三页的实际栏宽：

| 页 | 图片 | 比例 | 左栏宽 | 右栏宽 |
|---|---|---|---|---|
| P2 | 论文首页截图 | 0.75 | 3.94 in | 8.34 in |
| P3 | Fig.1 | 1.30 | 6.28 in | 6.00 in |
| P5 | Fig.5 | 0.81 | 4.24 in | 8.04 in |

**换了图就要重新核对右栏文案的字数**——右栏变窄后长句会断出孤行。
`check_text.py` 已改为调用同一个 `column_split()`，预检宽度与生成宽度一致。

### 附三：一个 run 里混排数字与中文，中文会掉成宋体

即使按规矩写了 `a:ea`，只要这一段以数字开头（「2026 年 10 月」「300–500 F/g
多取自低负载」），PowerPoint 就会用西文字体去排后面的中文，落到 Times 的
中文回退字（宋体）。同一页里一行黑体一行宋体，非常扎眼。

`engine.script_chunks()` 负责把每段文字按字符类别切开，逐块写 run：西文块用
Times New Roman，中文块用微软雅黑。全角标点、箭头、破折号（U+2010–U+2BFF）
归入中文块，与 `metrics` 的宽度口径一致。

### 附四：预检工具必须与生成逻辑共用尺寸参数

`check_text.py` 早期用固定栏宽做预检，与生成时的实际栏宽脱节，于是出现
「预检通过、渲染仍出孤字」。凡涉及宽度的预检，都必须从同一处取参数，
否则预检形同虚设。

### 附五：卡片的留白与层级间隔（"文字框是否美观"就看这组数）

三个参数在 `style.py` 的 `Style` 与 `engine.card()` 里，改任一个都要重算版面：

| 参数 | 取值 | 作用 |
|---|---|---|
| `PAD_X` / `PAD_V` | 0.22in / 0.18in | 卡片左右 / 上下内边距 |
| `CARD_GAP_PT` | 10pt | 卡内「标题 → 正文」的间隔 |
| 卡片之间的间距 | 由 `distribute()` 按剩余高度自动算 | 卡片与卡片的间隔 |

**三层间隔要有梯度，层级才立得住**：

```
框内留白 13pt  <  卡内层级间隔 15pt  <  卡片之间 19–23pt
```

判据是渲染图上的像素：文字到框线的实测留白不能小于 7.2pt（0.10in），
有标题的卡片，标题与正文之间不能小于 8pt。这两条都在第 5 维度里守着。

改参数后务必跑 `python tools/audit_all.py <pptx> <preview目录>`——
卡片变高会挤掉卡片间距，卡片变矮会把间距撑开，肉眼容易漏。

### 附六：孤行预检偏乐观，改完文案要用渲染图复核

`check_text.py` 按 `metrics` 的字符宽度估算断行，`audit_all.py` 读的是
PowerPoint 实际渲染出来的预览图。两者的末行占比会差 1–3 个百分点：

```
[预检] P10 卡片 也可以反过来指定目标   2行 末行0.20   ← 通过
[审计] 面板(0.42,3.09)              末行占比 0.16   ← 渲染后仍孤行
```

原因是估算把「结构—性能」这类含破折号、上下标的字符串按字面宽度算，
实际渲染时 PowerPoint 的词内断行位置不同。**所以预检通过不等于渲染通过**：
文案改动后必须重导预览图再跑一遍 `audit_all.py`，末行占比卡在 0.18 边缘
（0.18–0.22）的条目要主动多加两三个字。

这一次就是靠渲染复核抓出两条，各补两个字后通过。

## 开工先定六个数

页数、演讲时长、正文字号、画布比例、语速、备料冗余。这六个数决定一页能写多少字、
讲稿写多少字；不知道就先排版，等于把内容往一个没量过的框里塞。

```bash
python tools/intake.py            # 逐项问，直接给出每页字数区间与配置片段
python tools/intake.py --calc --pages 5 --minutes 5 --body-pt 14
python tools/intake.py --calc --pages 12 --minutes 8 --body-pt 20 --ratio 4:3
```

输出三样：整页满排字数、讲稿必讲与备料上限、每页建议区间。例如 5 页 / 5 分钟 /
14pt 给出正文页 295–537 字；同样的页数与时长，20pt 只有 150–260 字。
**字号一改，容量就变，字数区间必须跟着改**，否则一边报「内容单薄」、
一边排不下。

填进配置的两段：

```yaml
style:
  body_pt: 14
  min_pt: 14        # 判违规的下限；默认 20，本项目按当次要求改
compliance:
  chars_per_page:
    default: [260, 440]
    1: [150, 280]
```

## 数值怎么核

PPT 上的每个数字都要能回到原文。`tools/fact_check.py` 把配置里所有数值抽出来，
逐个到 `_src/paper.txt` 里找，找不到的列出来：

```bash
python tools/fact_check.py projects/<项目>/content.yaml
```

结果分三类：原文有的、白名单里的、找不到的。白名单是 `_src/facts_allow.txt`，
一行一个数，`#` 后写来源，只放过论文里本来就没有的外部数据：

```
14.7  # JCR 2024 影响因子，取自期刊官网，论文正文不出现
```

找不到的数只有两条路：改数，或补来源进白名单。**不要凭记忆写数**——
曾经凭空写出 55 Wh/L（原文只有 40 Wh/kg）、把 85 写成 80，
这类错在讲的时候会被当场问住。这一道是门禁第 5 项，生成前就拦。

没有 `_src/paper.txt` 时脚本会明确打印「跳过」并返回 0（不算失败）；
要真核对，先把 PDF 抽成 `_src/paper.txt`。比对按完整数值 token 做，
0.7 不会因为原文有 10.7 就算命中，30 也不会藏进 300。

## 综述怎么做

研究论文讲「一篇工作做了什么」，综述讲「这个领域怎么走到今天」。两件事要交的
东西不同，页序和版式也就不同：把「制备 / 性能 / 应用」三段套到综述上，
做出来的是一篇被拉长的研究论文。

| | 研究论文 | 综述 |
|---|---|---|
| 要回答的问题 | 它做了什么、为什么能做到 | 领域怎么演变、现在卡在哪 |
| 主线 | 现象 → 机理 → 性能 → 应用 | 文献 → 发展 → 转折 → 路线 → 卡点 |
| 版式 | 卡片、左右对照、图文页 | 时间轴、阶段带，配少量图 |
| 口吻 | 「本工作提出…」 | 「这个领域在 2006 年转向…」 |

### 页序骨架（示例：6 页 / 5 分钟）

页数由当次要求定，下面是综述常见的六段结构，可按需增删：

```
cover → fields_image（文献信息）→ timeline（双轨发展）
      → image_cards（转折点：一张图讲清范式怎么换的）
      → stages（材料路线逐级演进）→ cards_grid（卡点与方向）
```

字段写法见[页面类型.md](页面类型.md) 的 `timeline` 与 `stages` 两节；
`projects/_template` 演示的是研究论文常用的八种版式，综述两版式按文档字段
直接加进 `deck` 列表即可。

### 综述门禁：`review:` 段

综述最典型的失败不是「做得不好看」，而是「做成了研究论文」——页数够、字数够、
图也配了，可全篇只讲最近三年。这件事没有任何单项数值检查能兜住，所以单开一道。

```yaml
review:
  min_nodes: 10           # 时间轴节点下限（所有轨合计）
  min_span_years: 100     # 年代跨度下限：只覆盖近若干年，交的是现状不是发展
  require_types: [timeline]
  forbid_voices: [本文, 本研究, 该研究, 该论文, 本工作]
```

判据四条：时间轴页在不在；节点数与年代跨度够不够；每个节点是否写了「解决了
什么」（`head` 与 `desc` 都在）；全篇有没有冒出单篇口吻。

没有 `review:` 段就跳过，不算失败——研究论文型项目不受这条约束。
另一道会跳过的是事实核对（没有 `_src/paper.txt` 时）；除此之外的七道
对两类稿子一视同仁。

### 一句话里要带判断，不要带年份表

时间轴上最省事也最没用的写法是把年份和名词堆上去：「2006 亚纳米孔」。
读者看到的是两个词，不知道发生了什么。`head` 写这一步做成了什么，
`desc` 写它解决了上一段留下的什么问题，年份只是坐标。

## 样式怎么改

字体、字号、画布、边距、配色全在 `pptkit/style.py` 的 `Style` 里，是**数据不是常量**：
`content.yaml` 写 `style:` 段覆盖哪项，就只变哪项，代码不动。不写则该用默认值。

```yaml
style:
  cn_font: 思源黑体      # 中文字体，默认微软雅黑
  en_font: Arial         # 西文字体，默认 Times New Roman
  body_pt: 18            # 正文，同时决定行高与每页容量
  min_pt: 18             # 字号下限（合规查这一条）
  title_pt: 26
  cover_title_pt: 32
  slide_w: 10.0          # 4:3；16:9 是 13.333
  slide_h: 7.5
  margin_x: 0.42
  body_top: 1.10
  body_bottom: 7.08
  pad_v: 0.18            # 卡片上下留白
  grid_gap: 0.20         # 栅格列间距
```

**按页改字号。** 封面、信息页、内页的定位不同，字号不必统一。在页面里写
`body_pt`，只影响这一页，界面其余部分仍按 `style` 的全篇值：

```yaml
style:
  body_pt: 20          # 全篇默认
deck:
  - type: cover        # 封面走 20pt
    ...
  - type: image_cards
    title: 材料制备与各组分作用
    body_pt: 16        # 只这一页正文 16pt
```

页级覆盖同时把该页的字号下限定为 16：只写 `body_pt` 时，这个数就是该页的
下限；要另设下限就写 `min_pt`。反过来，页面写 `body_pt: 22`、全篇下限是 16 时，
该页仍按 22 判，不会退回 16 被放过。合规核对按页判，`check_text.py` 与
`build.py` 的容量估算也跟着用该页字号，算出来的行数才和实际一致。

**字号自适应（按页开关）。** 上面那套是「一页一个固定字号」；页数少、
每页字数差得多的稿子，固定字号要么撑不满、要么排不下。打开自适应，
每页在区间里自己挑：

```yaml
style:
  body_pt: 16            # 全篇默认，也是下限感的基准
  auto_pt: true          # 全局打开
  auto_pt_min: 16        # 区间下限（默认取 min_pt）
  auto_pt_max: 18        # 区间上限（默认取 body_pt + 4）
  auto_pt_step: 1        # 试探步长，0.5 更细但试排次数翻倍

deck:
  - type: timeline       # 这一页关掉：列宽由节点个数定死，字号一提就断行
    auto_pt: false
```

判据两条，按顺序：**先放得下，再不难看**。放得下＝在丢弃的 deck 上重排一遍
没有版面告警；不难看＝没把末行挤成一两个字（`auto_pt_orphan: true`，默认开）。
第二条是必要的：同一段话 16pt 排三行、18pt 排四行，末行只剩「壁。」，
放得下而难看，退一档更好。`orphan_ratio` 是这条线的阈值，默认 0.18。

页级覆盖（`auto_pt` / `auto_pt_min` / `auto_pt_max`）与全篇同一套键名，
写在页面里就只影响那一页。自适应选出的字号会打印在 `build.py` 的
「自适应字号」一行，可以直接看出哪页被压小了。

`check_text.py` 走的是同一个决策函数（`pages.choose_body_pt`），
报出来的行数与末行占比就是成品的样子；若它报孤行，说明这一页在区间内
**所有**字号都排不好，该改文案，不是调字号。

列宽被内容定死的版式（`timeline` 的节点列、`image_grid_cards` 的多列卡片）
不适合靠字号调松紧：字号一涨，说明文字多出来的那行会把整块撑高，
反而挤掉别的东西。这类页关掉 `auto_pt`，松紧交给 `tl_track_gap_max`、
`grid_grow_max` 这些间距参数。

`line_safety` 是行数估算的宽度折减：默认 0.97，中文密排、字号较小时
改成 0.94 更稳。0.97 时会出现「估一行、渲染两行」，卡片高度不够、
文字顶到框线——这类问题只在渲染图上看得出来，改成 0.94 才能在生成阶段拦住。

`body_pt` 与 `min_pt` 是两件事：`body_pt` 是实际排多大，`min_pt` 是判违规的下限。
两个都写同一个数，意思是「就按这个字号排，低于它算错」：
正文 14pt 就 `body_pt: 14`、`min_pt: 14`；要留余量排 15pt、下限仍守 14，
就 `body_pt: 15`、`min_pt: 14`。两个值都由这一次的要求决定，
框架不预设「应该多大」，默认值只是起点。

字段全表（`python -c "from pptkit.style import Style; print(Style.__dataclass_fields__.keys())"` 也可查）：

| 组 | 字段 | 默认 | 说明 |
|---|---|---|---|
| 字体 | `cn_font` / `en_font` | 微软雅黑 / Times New Roman | 中文必须写 `a:ea` 才生效，引擎已处理 |
| 字号 | `body_pt` `min_pt` `title_pt` `cover_title_pt` `cover_pt` | 20 / 20 / 30 / 38 / 20 | 正文、下限、页标题、封面标题、封面其余 |
| 字号 | `section_no_pt` `section_title_pt` `compare_label_pt` `bullets_lead_pt` `notes_pt` | 84 / 40 / 24 / 24 / 14 | 章节页、对照页、要点页、讲稿备注 |
| 自适应 | `auto_pt` `auto_pt_min` `auto_pt_max` `auto_pt_step` | false / 0 / 0 / 1 | 按页在区间内挑字号；0 表示取默认（min_pt、body_pt+4） |
| 自适应 | `auto_pt_orphan` `orphan_ratio` | true / 0.18 | 不许把末行挤成一两个字；末行占比阈值 |
| 行高 | `line_h` `line_safety` | 1.24 / 0.97 | 行高 ÷ 字号；行数估算的宽度折减 |
| 画布 | `slide_w` `slide_h` | 13.333 / 7.5 | 英寸。4:3 写 10 / 7.5 |
| 版心 | `margin_x` `body_top` `body_bottom` | 0.42 / 1.10 / 7.08 | 左右边距、正文区上下边界 |
| 版心 | `header_y` `rule_y` | 0.26 / 0.88 | 页标题顶端、分隔线位置 |
| 卡片 | `pad_x` `pad_v` `card_gap_pt` `card_line_w` | 0.22 / 0.18 / 10 / 0.75 | 卡内边距、标题与正文的段前距、边框线宽 |
| 卡片 | `cards_fit` `card_grow_max` `grid_grow_max` | true / 0.30 / 0.60 | 放不下时先收留白；内容少时每张卡最多加高 |
| 栅格 | `grid_gap` `card_min_gap` `card_max_gap` | 0.20 / 0.14 / 0.42 | 列间距、卡片竖排间隔的上下限 |
| 左图右文 | `col_r_min` `col_gap` `cap_h` `img_pad` | 6.0 / 0.21 / 0.32 / 0.06 | 右栏最小宽、栏间距、图注高、图框留白 |
| 左图右文 | `field_gap` `field_gap_max` | 14 / 22 | 字段段前距及其上限（pt） |
| 时间轴 | `tl_label_w` `tl_tick` `tl_rail_w` `tl_head_gap` | 1.30 / 0.075 / 0.012 / 0.14 | 轨名宽、节点方块、轴线粗细、轴线到文字 |
| 时间轴 | `tl_track_gap` `tl_track_gap_max` | 0.42 / 1.10 | 两条轨之间的最小 / 最大间距（in） |
| 阶段带 | `stage_year_w` `stage_year_pt` `stage_pad` | 1.62 / 22 / 0.26 | 年代列宽、年代字号、列与竖线及正文的间距 |
| 阶段带 | `stage_spine_w` `stage_gap` `stage_gap_max` | 0.012 / 0.24 / 0.75 | 竖线粗细、阶段之间最小 / 最大间距（in） |
| 配色 | `ink` `ink_2` `rule` `edge` `fill` `paper` | 黑 / 40 灰 / 9A 灰 / BF 灰 / F2 灰 / 白 | 写 6 位十六进制，如 `ink: "1A1A1A"` |

改样式的两个连带影响，改完要重跑全检：

1. **字号变，每页容量就变**——正文调大，同样的卡片数会放不下，`build.py`
   会报警「内容需 X in，可用 Y in」。这时要么减条目，要么调 `pad_v`/`card_min_gap`。
2. **画布变窄，图注容易折行**——4:3 下左图右文页的图框只有 3in 宽，
   20 字以上的图注会折行并被拦下，须缩短图注。

卡片留白是弹性量，且默认就弹性（`cards_fit: true`）：内容放不下时
`_stack_cards` 先把 `pad_v` 从 0.18 收到 0.14、把卡间距收到下限，
收到下限仍放不下才告警。所以同一套样式能容纳的字数是有弹性的，
但**不会靠牺牲留白硬塞**（0.14in 是渲染图上文字离框线的下限，
再低版式审计会判「顶到框线」）。

要复刻旧版版面（放不下也只按 `pad_v` 原样画、只告警）时，写 `cards_fit: false`。
默认开是有意的：能写多少字该由版心决定，不该由固定留白决定。

## 合规标准从哪来

阈值分两层，别混在一起：

| 层 | 谁定 | 写在哪 | 换一次汇报要不要改 |
|---|---|---|---|
| 引擎默认 | 框架 | `pptkit/style.py`（字体、字号、画布、边距） | 在 `style` 段覆盖 |
| 当次要求 | 每次汇报的通知 | `content.yaml` 的 `compliance` 段 | 改这里 |

`compliance` 段各字段管什么：

| 字段 | 管什么 | 示例值 |
|---|---|---|
| `max_pages` | 页数上限 | 5 |
| `limit_min` | 讲稿限时（分钟），不写则不查 | 5 |
| `time_buffer` | 备料冗余，加在限时上 | 0.4 |
| `chars_per_min` | 语速 | 220 |
| `chars_per_page` | 每页可见字数区间，不写则不查 | `[150, 260]` 或按页 `{default: [...], 2: [...]}` |
| `require_image_pages` | 哪些页必须有图 | `[2,3,4,5]` |
| `required_text` | 哪些页必须出现哪些字 | `1: [汇报人]` |

`docs/汇报要求.md` 是 2026-10-15 那一次的原文存档，作输入样例看，
不是框架标准。框架不内置任何一份要求：换学校、换课程、换页数，
只改上表右列，代码与文档都不动。

文献门槛（分区、影响因子、非综述）脚本判不了，人工选题时对着当次要求核，
结果记在 `projects/<项目>/核对记录.md`。

### 限时与冗余怎么设

`content.yaml` 的 `compliance` 段三个字段，一起决定讲稿能写多长：

```yaml
compliance:
  limit_min: 5        # 汇报限时（分钟）。不写 = 不查时长
  time_buffer: 0.4    # 冗余比例，默认 0.4
  chars_per_min: 220  # 语速，默认 220
```

**上限 = limit_min × chars_per_min × (1 + time_buffer)**。
5 分钟、冗余 40% → 7.0 分钟 → 1540 字备料。冗余**加在限时上**：先按 5 分钟
把话讲透（约 1100 字），再多备四成展开段。按 5 分钟写满、不留余量，翻一次页、
停两秒就超时；只写 3 分钟的量，内容又撑不起一场汇报，两头都不对。

多备的部分写在讲稿里，以「〔可略〕」开头，到空行为止：

```yaml
notes: |
  正文照读，讲 5 分钟。

  〔可略〕时间宽就往下讲，时间紧这一段整段跳过。
```

门禁算两笔账，任一笔超了都判失败：

| 口径 | 上限 | 管什么 |
|---|---|---|
| 必讲（去掉〔可略〕） | `limit_min × 语速` = 1100 字 / 5 分钟 | 跳过可略段能压回限时 |
| 全文 | `limit_min × 语速 × (1+冗余)` = 1540 字 / 7 分钟 | 备料没有灌水 |

`note_budget.py` 会报出超了多少秒、最长的是哪三页，`export_notes.py`
导出的讲稿每页标「必讲 N 字 / N 秒」，排练时对着看。

换一场汇报只改 `limit_min`；语速慢的老师把 `chars_per_min` 调到 180–200 更保守。

### 示例项目演示什么

| 项目 | 页数 | 演示的能力 |
|---|---|---|
| `projects/_template` | 9 | 研究论文常用版式：封面、章节页、图文页、卡片、对照、要点；新项目从这里抄结构 |

它跑通了引擎与全部门禁，但不是「标准答案」。新项目从 `_template`
抄页面结构，按当次要求改 `compliance` 与 deck 序列即可；页数、时限、
页序都不由文档规定。综述版式按[页面类型.md](页面类型.md) 的 `timeline` /
`stages` 字段加入 deck。

**配色说明**：默认黑白（`style.py` 的 `ink` / `rule` / `fill` / `paper` 全为灰阶）。
若确需其他配色，改 `style:` 段的颜色字段即可，但请先确认当次要求是否允许。
