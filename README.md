# 汇报 PPT 生成引擎（多项目）

生成「研究生文献汇报 / 课题汇报」PPT：字体、字号、画布、版心全部可配
（`content.yaml` 的 `style` 段），版式可量化验收。

**开工先问六个问题。** 页数、演讲时长、正文字号、画布比例、语速、备料冗余——
这六个数决定一页能写多少字、讲稿写多少字。`tools/intake.py` 把它们算成具体数字：

```bash
python tools/intake.py            # 交互式，一项项问，直接给出每页字数区间与配置片段
python tools/intake.py --calc --pages 5 --minutes 5 --body-pt 14
```

不知道这六个数就动手，等于先排版再猜容量，最后必然重写。

**页数与页序不写死。** 一页 = 内容配置里的一条记录，`type` 选版式、字段填内容，
换文献或换课题只改 YAML 与配图，不写代码。

- 页面类型速查 → [docs/页面类型.md](docs/页面类型.md)
- 操作步骤 → [docs/使用说明.md](docs/使用说明.md)
- 文风要求 → [docs/文风规范.md](docs/文风规范.md)
- 核对方法 → [docs/合规核对.md](docs/合规核对.md)

## 作为技能安装

仓库根目录本身就是技能目录：`SKILL.md` 是唯一入口，只写 `name` 与 `description`，不含任何
平台专用的面板配置。把整个仓库放进技能目录即可按 `$literature-report-ppt` 调用；
`SKILL.md` 是给 AI 看的操作流程，不是给人看的说明——人看本文件。

Linux / 无 PowerPoint 的机器上，预览图用 `tools/export_preview.py`（LibreOffice + pdftoppm）导出，
再用 `tools/audit_all.py` 审计；有 PowerPoint 时 `tools/verify.py` 会自动走完这一步。

现有项目：

| 项目 | 内容 | 页数 |
|---|---|---|
| `projects/_template` | 常用版式的可运行样例（引擎共 10 种版式，新建项目从这里抄） | 9 页 |

具体汇报项目只留在本地：`projects/*` 默认忽略，只保留 `_template`。汇报成品、讲稿、核对记录与论文插图都不入库。
模板样例稿 `projects/_template/示例_全部页面类型.pptx` 同样不入库，需要时用
`python tools/build.py projects/_template/content.yaml` 生成（每次重存都会改 zip 元数据，入库只会制造噪声）。

## 项目结构

```
pptkit/                引擎（与具体文献无关）
├── style.py           样式对象：字体 / 字号 / 画布 / 版心 / 配色（可配）
├── theme.py           默认样式的别名（旧脚本兼容，不随配置变）
├── metrics.py         文本度量：估算换行数、块高、末行占比
├── engine.py          Deck：文本 / 卡片 / 图片框 / 讲稿备注
├── pages.py           页面类型注册表（10 种版式，一页一个函数）
├── template.py        deck 配置解析与组装（兼容早期五段式配置）
└── compliance.py      合规核对

projects/<项目>/
├── content.yaml       该项目的全部内容（页面序列 + 文字 + compliance）
├── 核对记录.md        本地核对记录（不入库）
└── figs/              自论文抽取的配图（不入库）

tools/
├── verify.py          全检入口：文风 → 孤行 → 综述 → 讲稿时长 → 事实 → 生成 → 预览 → 合规 → 版式
├── style_check.py     文风体检（AI 腔句式、空标题、用词密度）
├── check_text.py      孤行预检（按各页版式算宽度）
├── review_check.py    综述门禁（时间轴、年代跨度、单篇口吻）
├── intake.py          开工参数与字数预算：页数、时长、字号 → 每页写多少字
├── fact_check.py      事实核对：配置里的数字逐个回原文找
├── note_budget.py     讲稿时长门禁（必讲 ≤ 限时，全文 ≤ 限时 × 语速 × (1+冗余)）
├── build.py           生成 PPT（含字号与版面溢出检查）
├── check.py           合规核对
├── audit_all.py       版式验收：全部页面 × 九个维度（核心门禁）
├── audit_gaps.py      间隔诊断（量某区域内每行的实际行间距）
├── export_notes.py    讲稿导出：notes → 纯文本（可选 Markdown），估每页用时
└── export_preview.ps1 导出逐页预览图

requirements.txt       运行依赖

docs/
├── 汇报要求.md        某次作业的原文存档（输入样例，非框架标准）
├── 使用说明.md        换课题的操作步骤、阈值从哪来
├── 文风规范.md        标题写法、AI 腔清单、规则来源
├── 页面类型.md        10 种版式的字段参考
└── 合规核对.md        核对方法：判什么、阈值从哪个字段读
```

## 常用命令

```bash
# 全检（推荐）：文风 → 孤行 → 综述 → 讲稿时长 → 事实 → 生成 → 预览 → 合规 → 版式
python tools/verify.py projects/<项目>/content.yaml
python tools/verify.py --all                                # 全部项目，末尾给汇总

# 讲稿：notes → 纯文本（每页字数与用时，语速取 compliance.chars_per_min）
python tools/export_notes.py projects/<项目>/content.yaml
python tools/export_notes.py projects/<项目>/content.yaml --md   # 需要 Markdown 时

# 只看页面清单，不生成
python tools/build.py projects/<项目>/content.yaml --pages

# 也可以单跑
python tools/style_check.py projects/<项目>/content.yaml   # 文风体检
python tools/check_text.py projects/<项目>/content.yaml    # 孤行预检
python tools/review_check.py projects/<项目>/content.yaml  # 综述门禁
python tools/note_budget.py projects/<项目>/content.yaml   # 讲稿时长
python tools/fact_check.py projects/<项目>/content.yaml    # 事实核对
python tools/build.py      projects/<项目>/content.yaml    # 生成
python tools/check.py <pptx> -c projects/<项目>/content.yaml
python tools/audit_all.py <pptx> <preview目录>
python tools/audit_gaps.py <preview目录>/slide2.png 6.18 1.05 12.95 6.60

# 导出逐页预览图（改完 PPT 后目视检查用；需显式传路径）
powershell -File tools/export_preview.ps1 -Ppt <pptx> -Out <preview目录>
```

版式审计基于**渲染图**。`verify.py` 会在生成后自动调这一步，手跑审计时
先确认图比 pptx 新，否则审计脚本直接退出码 2。`--skip-audit` 可跳过这一步
（换到没有 PowerPoint 的机器时用）。

## 质量门禁

验收标准是**全页 × 全维度**，不挑页也不挑维度。

| # | 门禁 | 脚本 | 检查内容 | 时机 |
|---|---|---|---|---|
| 1 | 文风体检 | `style_check.py` | 对偶转折、口号收尾、空标题、用词密度 | 动手前 |
| 2 | 孤行预检 | `check_text.py` | 每段文字断行后末行占比是否过低 | 生成前 |
| 3 | 综述门禁 | `review_check.py` | 时间轴在不在、跨度够不够、有无单篇口吻（无 `review:` 段则跳过） | 生成前 |
| 4 | 讲稿时长 | `note_budget.py` | 必讲 ≤ 限时、全文 ≤ 限时 × (1+冗余) | 生成前 |
| 5 | 事实核对 | `fact_check.py` | 配置里每个数字能否在原文找到 | 生成前 |
| 6 | 生成自检 | `build.py` | 字号是否 ≥ 该页下限、内容是否放得下 | 生成时 |
| 7 | 预览导出 | `export_preview.ps1` | 逐页 PNG，必须比 pptx 新 | 生成后 |
| 8 | 合规核对 | `check.py` | 页数 / 字体 / 字号 / 配图 / 必填项 / 每页字数 | 生成后 |
| 9 | 版式验收 | `audit_all.py` | 每页跑九个维度（见下表） | 生成后（需预览图） |

第 7 道由 `verify.py` 自动调用。单独跑 `audit_all.py` 时会先核对图的时间戳：
图比稿子旧、或某页缺图，直接退出码 2，不出「全部通过」——拿旧图审计，
量的是上一版版面，比不审更糟。

版式验收的九个维度：

| # | 维度 | 阈值 |
|---|---|---|
| 1 | 越界：元素是否都在页面内 | 容差 0.02 in |
| 2 | 重叠：非包含关系是否互相压盖 | 交叠面积 0 |
| 3 | 图片贴合：外框与图片比例是否吻合 | 死区 ≤ 12% |
| 4 | 框内居中：面板内文字上下是否对称（读 XML） | ≤ 6 pt |
| 5 | 卡内留白：上下留白是否够、是否对称；标题与正文是否分得开 | 留白 ≥ 7.2 pt、层级间隔 ≥ 8 pt |
| 6 | 孤行：末行占比 | ≥ 0.18 |
| 7 | 段间距：**同一文本框内**段落间隔极差 | ≤ 6 pt |
| 8 | 卡片间距：同栏相邻卡片间距极差 | ≤ 6 pt |
| 9 | 栏内填充：同排并列各栏底部留白 | ≤ 0.35 in |

第 7 项只适用于「一个文本框里排多个同类条目」的版面（如 P2 字段列表）。
封面刻意采用层级间距，改由「分隔线上下是否对称」单独检查。
第 8 项与第 7 项分工明确：**卡内的层级间隔**和**卡片之间的间距**是两回事，
混在一起比会得出无意义的极差（实测误报过 40pt）。
第 9 项只比较顶端一致的栏——顶端不同的属于纵向堆叠（如 P4 上排图、下排表）。

**纯计算查不出渲染层的居中与间隔问题，必须基于渲染图量像素。**

## 最容易踩的坑

**一、同一栏多段文字，间隔交给段间距，不要逐段定位。** 逐段定位时，估算
偏大的段会留下内部空隙，视觉间隔忽大忽小（实测过 19.8 / 45.0 / 18.0 /
18.6 / 45.0 pt，极差 25pt）。用 `engine.groups_text()`：整栏一个文本框，
段间用 `paragraph.space_before`，间隔由 PowerPoint 保证恒定。

**二、文本框内部边距必须归零。** 默认上下留 0.05 英寸、左右留 0.1 英寸。
不清零会导致版面算出的宽度与实际不符，文字被挤到下一行并整体下移。

**三、面板内文字交给 PowerPoint 居中；整页文字块却要自己算位置。** 早期用
「两个文本框 + 固定偏移」，实测上边距 18px、下边距 39px；改成 MIDDLE 锚点后
12 个面板上下边距差均 ≤3px。但**盒子远高于文字时锚点会偏下**：框高 5.98in、
文字 3.2in 时实测上下留白 1.7 : 1.0。原因是文字超出盒子时只向下溢出，并不对称。
所以卡片用 MIDDLE，整页文字块（bullets / compare）自己按度量算起点，
盒子高度取估算值再配 MIDDLE——估算偏小则上下各溢一点，视觉仍居中。

**四、字号提到 20pt 后不能凭经验估高度。** 必须按字体度量反推。系数（实测
标定）：中日韩 ≈ 1.00 em，数字 ≈ 0.50，大写 ≈ 0.60，小写 ≈ 0.42，空格 ≈ 0.25，
西文标点 ≈ 0.32；行高 ≈ 1.24 × 字号；可用宽度按 0.97 折算。另外
U+2010–U+2BFF 区间的箭头、破折号、℃ 在微软雅黑里按**全角**渲染，不能按西文
标点算，否则会少算一个字的换行。

**五、图片外框必须按图片真实比例贴合。** 固定外框会把图片缩在中间留下死区
（曾出现 65%）。一律用 `deck.image_framed()` / `deck.image_row()`。
若因宽度受限而填不满高度，`image_framed` 会把图块垂直居中，否则余量全堆在
图下方，看起来就是「图太靠上、下面空一块」。

**六、卡片的层级间隔必须大于框内留白。** 卡片里「标题 → 正文」的间隔靠
`CARD_GAP_PT`（10pt）撑开；它和上下留白（13pt）一起决定卡片读起来是否透气。
早期两级只隔 3–5pt，比框内留白还小，两行糊成一块——这正是「文字框不美观」
的根本原因。参数在 `Style` 里（`pad_x`/`pad_v`/`card_gap_pt`），改了要重算版面。

**七、卡片内边距取 0.18in，别再压。** 20pt 文字下边距小于约 0.10in 就顶到
框线。上下留白、层级间隔、卡片之间这三层间隔要有梯度：留白 13pt < 层级 15pt
< 卡片间距 19–23pt，层级才立得住。

**八、单图页的左栏宽要按图片比例反算，且不能挤窄右栏。** 写死左栏宽时，
比例偏宽的图会被宽度卡住、高度用不满（实测图下方空 0.73 英寸）。只按图片
反算又会走到另一个极端：图越宽左栏越宽，右栏被压缩，同一句话就多出一个换行。
故 `column_split()` 给右栏留下限 `style.col_r_min`（默认 6.0in，20pt 下约容 20 个汉字）。

**九、图片与下方的卡片必须共用同一套栅格。** P4 的图片原先按 `COL_L_W` /
`COL_R_W` 定列、卡片按两等分定列，两套栅格中线差了 0.3 英寸，同一列上下错开。

**十、预检工具必须与生成逻辑共用同一套尺寸参数。** `check_text.py` 早期用固定
栏宽做预检，与生成时的实际栏宽脱节，出现过「预检通过但渲染仍出孤字」。
现在两边都调用 `column_split()`。

**十一、YAML 裸键 `no` 会被解析成布尔。** 章节页序号字段一律写 `index`：
`no: "01"` 实际得到 `{False: "01"}`，序号静默消失（页面只剩标题与竖线）。
同类键还有 `yes` / `on` / `off`。

**十二、图注只能一行。** 图注区高度固定为 0.32in，折行会压到正文区。
`image_framed()` 在图注估算超过一行时告警，按提示缩短即可。

**十三、字段值折行要做悬挂缩进。** 每个值行是独立段落，只设 `marL` 会让首行
也缩进。正确做法：首段 `marL=hang, indent=-hang`（首行回到 0），其余段
`marL=hang, indent=0`（直接从句首缩进处起排），折行才与值的左端对齐。

**十四、一个 run 里混排数字与中文，中文会掉成宋体。** `a:ea` 写了也没用：
像「2026 年 10 月」「300–500 F/g 多取自…」这种以数字开头的 run，PowerPoint 用
西文字体去排后面的中文，落到 Times 的中文回退字（宋体），一行里出现两种字形。
修法是按字符类型拆 run：`engine.script_chunks()` 把每段文字切成「西文块 / 中文块」，
逐块设字体，纯中文块才真正用上 `a:ea`。这条对全篇生效，不只是封面。

**十五、AI 腔不靠肉眼扫，靠规则表。** 「不是…而是」「而非」「一句话」「值得注意的是」
这类句式单看每句都通顺，连读十句才露馅，人眼一遍遍扫必然漏。`tools/style_check.py`
把清单做成正则，逐字段逐句报位置。第一份综述稿曾命中 22 处（严重 10），
改完清零。规则表抓不住空洞，只抓句式，所以它排在第一道、不排最后一道。

**十六、孤行预检偏乐观，文案改完必须用渲染图复核。** `check_text.py` 按字符宽度
估算断行，`audit_all.py` 量的是 PowerPoint 渲染结果，两者末行占比能差 1–3 个百分点。
实测 P10 两条预检 0.20 通过、渲染后 0.16 仍孤行，各补两个字才过。
**预检通过 ≠ 渲染通过**，末行占比落在 0.18–0.22 边缘的条目要主动留余量。

**十七、YAML 列表项里出现「: 」会被当成键值对。** 封面 `meta` 写
`- Nat. Commun. 2026, DOI: 10.1038/...`，PyYAML 解析成
`{"Nat. Commun. 2026, DOI": "10.1038/..."}`，随后 `script_chunks()` 拿到 dict
的键去逐字符处理，报 `ord() expected a character, but string of length 22`——
错误信息离现场很远。凡值里带英文冒号加空格，一律加引号。同类还有网址、
`时间: 14:30` 这种写法。

**十八、标题里的逗号是最隐蔽的 AI 腔。** 把「不是…而是」全改掉之后，
标题仍然一水儿是 `同一块碳，电容从 85 涨到 172 F/g` 这种形状——逗号左边铺垫、
右边结论，读的人要在半句处换一次焦点。它和「不是…而是」是同一个病：
**把两个判断折叠进一句**。十二页十二个逗号，删句式删不掉，得改句子架构。

改法固定：前半句压进主语，整句收成一个主谓宾。
`同一块碳，电容从 85 涨到 172 F/g` → `同一块碳的比电容从 85 涨到 172 F/g`；
`软包 40 Wh/kg，循环三万次`（两个并列事实）→ `软包电芯循环三万次容量保持七成`，
能量密度挪进卡片。真有两个判断就拆页。

`style_check.py` 现在把 `，：；` 判为严重，小标题（`cards[].name`）一并查，
冒号放行以兼容 `EC:DMC` 这类化学写法。依据是 Minto「Use statements not
captions」与 High Bridge Academy 第 1 条「no fragments, no colons」——
不是我个人的排版偏好。

**十九、文献汇报的标题不是「结论」的位置。** 前一条把逗号治了，条数对，方向偏：
我把咨询公司给阅读型 deck 写的 action title 套到了文献汇报上，把每页标题都改成
`同一块碳的比电容从 85 涨到 172 F/g` 这种判断句，其中一页写成
`该文 2026 年发表于 Nature Communications`。三个问题：结论是作者的、不是汇报人的；
下面七行字段已经写了期刊分区，标题再复述一遍纯冗余；听众抬头那一秒只需要知道
「在讲哪一块」。**文献汇报的标题照当次要求里每一页的原话写**
（论文基本信息 / 材料制备与各组分作用 / 主要性能与成因 / 主要应用），
封面用论文题目中译。封面另造一句总结还有个副作用：与第二页的英文原题对不上，
翻页时听众以为讲了两篇。判断句的写法留给「讲自己的研究」那一类。

**二十、限时是第一个该问的数；四成冗余加在限时上，不从限时里扣。** 前面几轮都在
改字句和版式，没人问过「这稿子念出来多久」——直到讲稿写到 1063 字才发现限时
（后来确认为 5 分钟）早超了，项目里连个可配的时限都没有。补上 `compliance.limit_min`
+ `time_buffer` 之后，第一版把冗余做成了减法：5 分钟 × 60% = 3 分钟、605 字，
讲出来 2.8 分钟，还自以为留了四成余量。方向反了——5 分钟是**要讲到的量**，
四成冗余**加**在这 5 分钟上，备料 7 分钟、1540 字，多出来的写成〔可略〕段，
现场时间紧整段跳过。门禁因此算两笔账：必讲 ≤ 5 分钟（跳可略能压回来），
全文 ≤ 7 分钟（备料没灌水）。**冗余加在被保障的量上，不是从它里面扣。**
时限、页数、听众人数，开工前先问，别等做完再倒推。

**二十一、PPT 上的字数也是可配的，别让「写死」把内容压扁。** 有反馈说
「每页字数太少」，查下来三处原因叠在一起：一是排版参数（字体、字号、画布、
边距、卡片留白）全是 `theme.py` 的模块级常量，被三十多处 `import` 按值绑定，
运行时改不动；二是卡片区按固定 `pad_v = 0.18in` 排版，四张卡光留白就占 1.44in，
多写两行正文必然溢出，于是只能少写；三是**没有任何一条门禁管「这一页写得太少」**，
合规只查「不超页数、字号够大」，写三句话和写三百字一样通过。

改法分三处：

1. `pptkit/style.py` 立 `Style` 对象，`content.yaml` 的 `style:` 段可覆盖
   字体、各级字号、画布（16:9 / 4:3）、版心、卡片留白、配色；引擎与版式
   一律从 `deck.style` 取，`theme.py` 退化成默认值别名。默认值与原行为
   逐像素一致（改造后用同一份配置生成两份 pptx，49 个形状坐标零差异）。
2. `_stack_cards` 把留白当弹性量，且**默认就弹性**（`style.cards_fit` 默认 `true`）：
   内容多时先收 `pad_v`（0.18 → 0.14）、再收卡间距，都到下限仍放不下才告警。
   留白可以退，字数不该被留白卡死。曾经把这开关默认设成关（为复刻旧版面），
   结果字数一多就被判「放不下」，等于又把这件事塞回写死的老路——改回默认开，
   要复刻旧版面时才显式写 `cards_fit: false`。
3. `compliance.chars_per_page` 给每页字数区间，低于下限报「内容单薄」、
   高于上限报「内容过密」，可按页覆盖（封面含英文标题、信息页含论文题目
   全文，天然比别人多）。

教训：**「没写死」不能靠嘴说，要看配置里有没有这个字段。** 只要一个量
只能改代码才能变，它就是写死的——哪怕它在文件里长得像常量。
**加了开关却默认关掉，等于没加。**

**二十二、预览图不是附件，是门禁的输入。** 版式审计量的是 PNG 像素，
而导图一直是独立的手工步骤：改了 `pad_v`、重建 pptx，图还是上一版的，
审计照样「全部通过」（它量的是旧版面），汇报时才发现卡片贴框。
两处补上：`verify.py` 于生成后自动导图（第 7 步），导不出就判失败、
不拿旧图顶替；`audit_all.py` 单独跑时先核对时间戳，图比 pptx 旧或缺图
直接退出码 2。**凡是审计依赖的中间产物，都要在门禁里生成并校验新鲜度。**

**二十三、页数、时长、字号不知道就别动手。** 这三个数决定一页写多少字、讲稿写多少字，
却一直没人问，都是先排出样子再倒推内容，于是反复出现「字数太少」「放不下」「讲超时」。
现在 `tools/intake.py` 把六个问题（页数、时长、字号、画布、语速、冗余）问一遍，
直接算出每页字数区间与讲稿字数，写进配置。**先定容量，再填内容。**

**二十四、PPT 上的每个数字都要能回到原文。** 曾经凭记忆写出 55 Wh/L（原文只有
40 Wh/kg）、把 85 写成 80、把「保持 71.4%」写成「不衰减」——都是讲的时候会被
当场问住的错。`tools/fact_check.py` 把配置里的数字全抽出来，逐个到 `_src/paper.txt`
里找；找不到就报出来，要么改数，要么进 `_src/facts_allow.txt` 并写清来源
（影响因子、分区这类论文里没有的外部数据）。这是第 5 道门禁，生成前就拦。

另外：python-pptx 的 `font.name` 只作用于西文，中文必须在 `a:rPr` 下写 `a:ea`
节点指定东亚字体。中文长句换行易留孤行，用 `tools/check_text.py` 检出。

## 环境

- Python 3.10+，命令按环境写成 `python`（Windows 上通常是 `py` 或 `python`）
- 依赖：`python -m pip install -r requirements.txt`（python-pptx / PyYAML / Pillow / numpy），
  抽图另需 `pymupdf`
- 预览导出依赖本机 Microsoft PowerPoint（COM 接口）
- `tools/export_preview.ps1` 含中文路径，必须存为 UTF-8 with BOM，
  否则旧版命令行宿主会按 ANSI 解析导致路径乱码
- 测试：`python -m unittest discover -s tests`
- 许可：MIT，见 [LICENSE](LICENSE)
